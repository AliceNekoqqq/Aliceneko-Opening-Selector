# 红豆粉开场白选择器 · Aliceneko Opening Selector

红豆粉（Aliceneko）制作的独立源码项目。当前正式版 v1.0.12 是一份轻量通用脚本：玩家把它放在酒馆助手全局脚本库，作者把同一份脚本放进角色脚本并随卡导出。普通多开场卡显示玩家预览；主开场以 `<UniversalOpeningSelector/>` 开头的卡显示作者选择页。与《丧尸少年》专用选择器无关。

插件界面与通用脚本均带有来源水印：`唯一来源Discord:♡Aliceneko♡/红豆粉丨本插件完全免费`。

未经作者同意，不得二次修改或基于本插件进行二次创作；禁止任何形式的商业使用。

## 普通用户：原卡直接使用

在酒馆助手的**全局脚本库**导入 `dist/红豆粉开场白选择器_通用脚本_v1.0.12.json` 并启用，不需要修改或重新打包别人的角色卡。这与作者导入的是同一份文件。

打开拥有主开场和至少一条备用开场的普通角色卡，新建聊天。首条消息上方出现“预览开场”入口；卡片标题取正文第一句，完整原文仅在展开预览中显示，选择后切换首条消息页。第一条开场仍是原卡正常显示的正文，索引为 0；后续开场依次为 1、2……。已经有后续聊天消息时入口隐藏，群聊暂不支持。脚本不会写入普通角色卡或聊天正文；不要求正则或作者配置；脚本首次导入后会自动读取 GitHub 上的小型版本指针，再加载对应的固定提交运行模块；发布新版本后，玩家刷新页面即可使用更新，无需反复导入脚本。运行时需要联网。若卡片主开场以选择器标记开头，通用脚本切换到作者模式。

普通用户模式的主题、入口拖动位置、开场标签以及标题和人物修正可仅保存到本机。预览窗口整体滚动，卡片可展开“预览完整正文”，并支持搜索开场、按人物筛选、按需排除标题中的指定 `<字段>`；作者也可将标题排除字段与标题／人物修正写入角色卡。预览弹窗中的“自定义开场标签”可逐条填写并保存；留空恢复卡片原标签。作者版在“设置 → 开场白 → 标签”填写，保存后从酒馆重新导出，标签会随角色卡分享。触摸或鼠标拖动“预览开场”按钮可移动入口，轻点仍打开弹窗；拖动按屏幕刷新节奏合并位置更新，视口变化时位置会限制在屏幕内。标题提取会跳过开头的代码块、注释以及除 `<正文>`／`<content>` 之外的成对标签块，只从这两种标签内或标签外的普通文字提取叙事标题；展开预览始终显示原开场全文。测试版的人物识别先建立角色绑定世界书的人物名单，再用姓名与别名匹配开场全文，包含所有标签、属性、注释与代码块。开场卡片的登场人物仅显示姓名，不附带自动提取或作者／玩家填写等来源提示；作者和玩家可在“人物识别规则”查看提取名单、别名、世界书条目来源及冲突别名，也可手动补充人名与别名。人物识别不再排除 `<字段>`，旧 `excludedPersonTags` 设置不参与匹配；标题排除规则仍独立生效。人工修正优先于自动结果。脚本关闭或替换时清理旧按钮和观察器，重新运行同一版本也会重新挂载。脚本识别作者版首条消息的 `<UniversalOpeningSelector/>` 标记，自动避让作者版页面。某些酒馆版本或其他插件可能改变首条消息的消息页结构；脚本会核对可用页数，无法安全切换时不会改动聊天。

## 作者：在角色卡内启用选择页

作者将同一份 `红豆粉开场白选择器_通用脚本_v1.0.12.json` 导入该卡的**酒馆助手角色脚本**，不需要下载源码、运行 Node 或手动编辑 JSON。请先安装并启用酒馆助手。

1. 打开要制作的角色卡，将**主开场白**改为下方的固定标记（可在后面加一段未加载时的提示）：

   ```text
   <UniversalOpeningSelector/>

   【请选择开场】如果选择页没有出现，请使用酒馆首条消息的翻页箭头。
   ```

2. 把原来的主开场移到**备用开场第一条**，其余备用开场按原顺序排在后面。不要把选择页标记放进备用开场。
3. 在该角色卡的**酒馆助手角色脚本**中导入通用脚本并启用；确认该脚本会**随角色卡导出**。
4. 新建聊天，首条消息显示选择页。在右上角 **设置** 中编辑标题、导语、每条开场的标题／标签／登场人物／简介／封面、自定义排除字段、人物与别名、主题、BGM 与歌词。点 **保存到角色卡**，等待保存及复核成功提示。
5. 从酒馆正常导出角色卡，再重新导入一份检查开场页与脚本是否随卡保留，随后分享给玩家。

选择页只在首条消息仍是标记、聊天尚未继续时显示。重复打开设置与保存不会迁移或复制开场；插件只读取备用开场，不改动作者写好的正文顺序。已经使用旧版打包器制作的卡仍可按原方式运行。
普通卡未加标记时会进入玩家模式，因此作者须先按上述步骤设置主开场和备用开场，再新建聊天检查作者选择页。脚本不会自动搬移开场；若标记已设置但聊天仍显示旧开场，请保存角色卡并新建聊天。

## 数据与媒体

角色卡名称仅作为待验证线索，不再直接当已确认人名；姓名形态的卡名仅被正文提及时列为待确认，正文明确姓名／人物名单、世界书或人工词表确认后才进入筛选。自动提取排除“莉娜的故事”等所属短语及英文所有格短语，保留“顾之遥”等真实姓名；手动规则可确认特殊虚构姓名。旧版已经保存到人物字段的内容仍按人工填写优先，若保存过误判标题，请在人物字段删除后保存。

测试版 beta.13 将“已确认姓名”和“待确认候选”分开。明确姓名字段、姓名标签、人物 `name` 属性、带姓名列的表格和明确人物名单可确认身份；普通标题、年龄／性别／外貌／代词描述以及触发关键词均不能单独确认姓名。人物速览中的普通文字与标题先列为候选，无姓名列的表格不作为人物名单。正文中没有已确认姓名依据的台词署名和人物标签也先列为候选；候选被提及不会自动进入人物筛选，也不会跨开场传播。可在“修正标题和登场人物”采纳，或在“人物与别名”手动确认。正文明确姓名可继续补充词表并跨开场匹配，空世界书或读取失败不会清空明确姓名。

详细规则、复现问题和准确性边界见 [人物匹配规则审查](docs/person-matching-audit.md)。beta.13 的姓名证据读取器由世界书与开场正文共用；通用 `name`／`名字` 需要人物语境，明确物品／组织与示例范围不会建立人物身份。人物名单到其他章节时结束，删除了把名单长句分词截成人名的路径。重复手动别名显示冲突，不再由最后一行覆盖。

**世界书触发关键词不等于别名。** beta.13 只将明确的别名／昵称／称呼／小名／曾用名／英文名／外文名／`alias`／`aliases` 字段，以及人物速览的别名列作为自动别名来源。普通关键词显示为“待确认关键词（未用于匹配）”，即使看起来像人名也不自动参与匹配；需要时可手动填写 `沈挽昼=挽昼,小沈`。触发关键词不能建立条目身份或别名归属，身份不明的关键词仅列在诊断里；其他人物的正式姓名、通用称谓、分类与评级词不会挂成别名。明确别名冲突时展示冲突并停止自动归属，手动指定仍优先。

测试版仅读取当前角色绑定的主／附加世界书，兼容 `getCharWorldbookNames/getWorldbook` 和旧版 `getCharLorebooks/getLorebookEntries`，旧条目 `keys` 也只作为触发关键词处理。接口缺失时按角色卡保存的 `extensions.world` 主书绑定读取，不额外读取卡内嵌入条目、全局世界书或聊天世界书。新增的开场世界书预设也沿用这一绑定范围，只按条目 UID 切换启用状态，不改条目内容；绑定书读不全或 UID 已变化时会停止应用，避免不完整切换。支持编号、装饰、括号、分隔符标题、Markdown／JSON／YAML／XML 姓名格式与“名叫／姓名为”描述，保留日文、数字、全角及单字姓名。整书分类推断只以至少 3 个已确认独立姓名为依据，仅在本书生效，保留真实复合姓名并过滤 NPC／NSFW／SFW／R18 等评级标签。全文匹配包含所有标签、属性、注释与代码块，长姓名优先，英文按单词边界、单字按保守边界匹配。世界书名单是优先词表，不是排斥其他明确姓名的白名单。

“人物识别规则”展示姓名、已确认别名、待确认关键词、条目来源、绑定书名、读取本数、条目数与失败／未采纳原因，可重新读取。禁用条目跳过，词表上限为 1000 人。人工姓名修正与手动词表继续优先；旧版保存过的误判需要在人物字段清空后保存，以恢复自动识别；作者和玩家字段均支持留空恢复，输入“无”则明确隐藏人物。规则不调用 AI、不改世界书；任意自由文本无法保证完整识别，姓名被提及也不代表人物一定在现场。

- 作者设置及上传的封面、音乐、歌词数据保存在 `data.extensions.universal_opening_selector`，与远程模块的缓存及更新相互独立；角色脚本带 `export_with.data=true` 随卡导出。保存时检查酒馆服务端写入响应，并从角色卡读取接口复核配置，然后同步当前角色数据；无法复核时不会提示保存成功。导出更新后的角色卡可随卡分享。
- 封面、音频用 Data URL 内嵌在卡内；歌词存为文本。这样不会引用作者本机文件。封面原图限 8 MB，上传时尝试缩到最长边 960 px 并转 WebP；仅在更小时使用压缩图，保存结果仍限约 1 MB，GIF 保留动图原样；音频限 8 MB；角色卡体积会显著增加。
- 无封面时显示当前主题的编号、渐变与排版，不依赖默认图片。
- 作者设置可展开查看每条原开场正文，对照填写标题和简介；这里只读，原文不会被改写。卡片标题、简介、标签和封面有实时预览；关闭未保存的设置会撤销播放器预览。
- “从原文生成文案建议”使用本地文本规则，点击后仅填入该条的标题和简介编辑框，不调用 AI，也不修改正式开场。作者检查后自行保存。
- 设置中的“制卡检查”显示正式开场数量、作者角色脚本状态、扩展字段及当前角色数据体积。它依据酒馆当前内存数据，不能代替导出角色卡后的重新导入验收。
- BGM 设置在独立标签页，启用开关控制播放器显示与播放，上传后可预览，点击保存写回角色卡；播放器参考《丧尸少年》的唱片、进度条和歌词布局，并跟随主题变色。音乐需手动播放；支持 LRC 时间标签及 TXT（TXT 显示全文，不逐行同步）。作者应确认分享媒体的权利。
- 作者默认主题随卡保存；玩家临时切换的主题单独存于本机。

## 实现与限制

通用脚本作为角色脚本导入时会随卡保存；作为全局脚本导入时供普通玩家使用。它读取 `<UniversalOpeningSelector/>` 标记来区分两种界面；不需要额外的 Regex；导入的同一份脚本仅包含 GitHub Loader，运行时需要访问发布源。玩家的酒馆仍须安装并启用能够运行角色脚本的酒馆助手。选择开场使用酒馆助手的 `setChatMessages` 切换首条消息页。作者设置保存到 `data.extensions.universal_opening_selector`，不改写开场正文。

如果作者只填写标记却没有导入随卡导出的角色脚本，选择页不会出现，首条消息保留原生翻页提示。群聊与已经开始的聊天不显示选择页。不同酒馆版本及其他插件的消息渲染方式仍需在实际环境中验收。

## 主题

旧档案使用深海蓝和古铜档案线，霓虹夜使用纯紫粉光晕，纸与墨使用暖纸纹与墨色，黑白电影使用胶片框线，林间信使用深绿和叶脉纹，锦书古风使用胭脂暗底、描金卷轴与朱砂纹饰；另有星海航图、绯色契约、末日警报，共九套主题。每套主题现在有专属全幅背景图：分别对应档案书库、紫粉霓虹城、纸本水墨山峦、黑白雨夜、林间晨雾、古典园林、星海图、绯色花影和末日废城。背景在上半区保持清晰并自然渐隐到主题原底色；本版进一步提高背景不透明度并延后渐隐起点；作者选择页和玩家预览均随主题切换，不遮挡开场正文。九套主题各有透明底主题小徽记：展示在页眉、开场卡、主题切换预览和搜索无结果提示；古风封面的“卷·故事”标签固定横排，不再拆行。作者设置的三个分类页签配有开场书页、唱片和检查单插画；没有开场时显示书页提示，搜索无结果时显示当前主题徽记，BGM 为空时显示唱片插画。主题徽记约 72 KB，三个设置小图约 13 KB，九张背景约 312 KB，均随远程运行模块加载，不增加角色卡数据。主题按钮在设置按钮左侧；主题和设置参照 MR-87 收音机，在酒馆主页面的独立 iframe 中显示；主题与设置均使用可拖动的独立浮窗，去除外层黑色方边，背景无遮罩且可见；手机端窗口自适应屏幕，内部滚动并保持关闭／保存按钮可见。选择页手机端使用直角外框，避免酒馆消息容器的黑色背景从四角露出。切换开场再返回选择页时会重新挂载。

## 开发

`src/author.js` 是标记识别与作者选择页挂载逻辑；`src/player.js` 提供普通玩家模式；`src/selector.js`、`src/selector.css` 实现作者界面。`scripts/build-author-script.mjs` 生成仓库的 `remote.js` 运行模块和轻量导入脚本。`pack.mjs` 保留为开发与回归测试工具，不属于作者使用流程。

在 `develop` 上运行 `node scripts/build-author-script.mjs --preview` 构建测试运行模块和测试导入脚本；正式构建 `node scripts/build-author-script.mjs --stable` 只允许在 `main` 上执行。构建后执行 `node test/author.test.mjs`、`node test/player.test.mjs`、`node test/worldbook.test.mjs`、`node test/worldbook-presets.test.mjs`、`node test/person-rules.test.mjs`、`node test/pack.test.mjs`、`node test/observer.test.mjs`、`node test/loader.test.mjs`、`node test/confirmed-loader.test.mjs` 和 `node test/update-control.test.mjs`。本阶段列出的十个 Node 回归脚本已通过；当前环境没有 Playwright Chromium 可执行文件，作者 UI 自动化与真实酒馆／手机验收仍待完成。有 Playwright 浏览器环境时执行 `node test/author.ui.test.mjs`，覆盖玩家／作者入口和世界书预设的创建、编辑、保存、撤销、分配及切换。角色脚本在酒馆中导入、保存、导出后还需做现场回归。

玩家窗口和作者选择页角落均标明当前脚本版本。作者页可搜索标题、人物和正文，并按登场人物筛选；作者卡片采用简短摘要，自动识别登场人物，并能识别旧版自动生成的标题；点击“预览完整正文”查看原文，开场数量较多时保持网格浏览。

## GitHub 加载与素材保留

导入的 JSON 只包含轻量启动器，不内嵌运行源码。作者将它导入角色脚本并勾选随卡导出后，角色卡会带着启动器；作者预设和媒体仍保存在卡片扩展字段。

正式版 v1.0.12 的更新入口位于设置：玩家端为「版本与更新」，作者端为「更新」页签。可关闭「启动时自动检查更新」，关闭后仍能手动检查。发现新版后，先展示当前版本之后的逐版本更新内容，确认后才下载运行模块；取消后不重复弹出该版本，版本号旁仅保留小星标。

更新说明使用插件内确认窗口，检查进度、最新版本及失败原因显示在设置内；指针／说明请求有超时处理。设置／主题浮窗让酒馆通知显示在上方，并裁切圆角黑底。「更新」页签有透明插画；手机页签上下排列。

v1.0.12 已修复预设再次编辑、开场文案漏存、旧格式世界书开关与切换角色竞态。手动检查前、下载前及替换模块前会处理未保存设置，选择继续编辑会暂停更新。作者预设、封面与音乐保存在角色卡扩展字段中。

**从 v1.0.11 及更早正式版升级，请替换一次 `红豆粉开场白选择器_通用脚本_v1.0.12.json`。**旧启动器仅更新远程模块仍保留旧入口／系统弹窗，无法获得新的更新窗口、检测开关和完整草稿保护。替换前先保存编辑内容，并停用测试脚本。之后更新运行模块可直接从设置确认，无需每次导入。运行模块依次尝试 jsDelivr、testingcf 和 GitHub Raw，联网是使用前提。审查范围及实机验证边界见 `docs/release-audit.md`。

## 测试版与正式版

正式用户安装上述 v1.0.12 通用 JSON。它始终读取 `main/scripts/runtime-ref.txt`，正式指针只在功能完成验收、正式运行模块发布后更新。开发改动提交到 `develop`，不会因为测试分支有新提交而进入正式用户脚本。正式 Loader 也会拒绝带 `-beta.N` 的测试运行模块。

参与测试时导入 `dist/红豆粉开场白选择器_测试版脚本_v1.0.10-beta.11.json`。测试脚本有独立 ID，默认关闭，只读取 `develop` 预览指针；测试前先停用正式脚本。作者在“设置 → 世界书”集中管理预设，再给各开场分配预设。beta.1 保存的逐开场设置会自动迁移。

维护者发布测试版时，先把包含 `remote.js` 的测试源码提交并推送到 `develop`，再把该提交 SHA 写入测试指针、重新构建测试 JSON 并推送。正式发布时先将验收通过的源码提交到 `main`，生成并验证正式运行模块；在该运行模块提交已发布后，最后更新正式指针。`main` 的正式指针保持不动，直至正式发布的最后一步。

测试版 v1.0.10-beta.11 将更新入口并入设置，提供启动时自动检查开关和逐版本更新说明；取消后收起更新弹窗，版本号旁用星标提示仍有新版。此前 beta.6 已加入玩家切换开场前的未保存确认、作者与玩家关闭前提醒，以及按开场应用世界书预设。
