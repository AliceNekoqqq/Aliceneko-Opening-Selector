# 红豆粉开场白选择器

正式版 **v1.0.19**。玩家与作者使用同一份酒馆助手通用脚本，为多开场角色卡提供搜索、预览和选择入口。
本次正式版新增开场白生成、独立人物列表与分页面问号教学；主题缩略图使用真实背景并保留编号与图标，同时加强人物读取、角色卡保存和弹窗清理。

## 安装与使用

需要安装并启用酒馆助手，运行模块及默认图片需要联网加载。

玩家将 [正式通用脚本](dist/红豆粉开场白选择器_通用脚本_v1.0.19.json) 导入酒馆助手全局脚本库并启用，打开普通角色卡、新建聊天，在首条消息附近点击「预览开场」。若卡片已自带并启用脚本，可直接使用。已继续的聊天与群聊不显示入口。

作者完全在酒馆里制作：

1. 将主开场改为以下内容，并将原主开场移到备用开场第一条，其余按原顺序排列：

   ```text
   <UniversalOpeningSelector/>
   【请选择开场】如果选择页没有出现，请使用酒馆首条消息的翻页箭头。
   ```

2. 在角色脚本中导入同一份通用脚本并启用，确认随角色卡导出。
3. 新建聊天，在「设置」编辑选择页、各开场、封面、音乐和世界书预设，点击「保存到角色卡」。
4. 从酒馆导出角色卡，建议重新导入确认设置、脚本和媒体保留。

不需要角色卡打包器、Node、手工 JSON 或源码编辑。插件不会自动搬移原开场。

## 功能

正式版 **v1.0.18** 新增开场白生成：玩家点击「创建新开场白」，作者点击「生成开场白」，选择人物并填写创作要求，使用当前主 API 生成；编辑确认后加入角色卡备用开场。支持结构参考、修改方向重写与最近五份本机草稿恢复。普通单开场卡与空备用开场作者卡也可使用。[功能设计与适配边界](docs/opening-generation.md)。

- 作者与玩家主界面的「人物列表」可搜索、勾选、补充、确认已勾选人物，或删除未勾选／待确认项；保存后按角色在本机共用，取消可撤回，恢复读取名单可找回删除项。
- 各页面与主要模块分别提供问号教学，说明选项、按钮及保存范围。
- 搜索标题、人物和正文，按人物筛选，预览完整原文；支持手动修正与标题排除字段。
- 随机抽取入口随主题使用不同名称和专属卡背（例如锦书抽签、霓虹解码、月下御签、放课后奇遇）。每轮摆三张或五张不同开场的主题卡背，洗牌后手动选一张，翻开揭晓封面、标题与简介，可重抽、预览正文或确认进入。玩家当前开场不参与；抽取不会自动切换消息，简洁模式与系统减少动态效果跳过演出和翻转，仍等待手动选卡。可在作者「设置 → 开场白 → 页面信息」或玩家「设置 → 功能开关」开关盲盒抽卡；默认开启，按角色保存在本机，关闭隐藏盲盒与卡池入口，重新开启保留原设置。入口下方的「卡池与抽卡设置」支持沿用首页筛选或手动勾选整卡开场，可搜索、全选、清空与仅选当前筛选；手动范围独立于首页筛选，按角色保存在本机，空选不扩大范围。支持保存、切换、更新、重命名和删除命名卡池，设置统一应用后生效。
- 点击卡片旁的 ☆ 收藏开场，再点「只看收藏」快速筛选；可与其他筛选条件组合。收藏按角色保存在本机，作者与玩家共用，不随卡片导出；原文修改后需重新收藏。
- 十七套独立主题，85 张默认封面。默认封面按本机随机种子分配，可重复，搜索与筛选保持稳定，自定义封面优先。
- 作者可编辑页面标题、导语、开场标题、简介、人物、标签和封面。设置分组编辑，保存入口固定。
- 作者可分别控制选择页看板娘 Logo 和「红豆粉开场白选择器」大标题，随角色卡保存默认显示；玩家可按角色在本机单独覆盖。底部来源信息始终保留。
- 新增画廊、故事目录、档案版式，旧卡默认原有排列；作者在「设置 → 开场白 → 页面版式」保存默认值，普通玩家可在首页按角色切换本机版式。
- 作者在逐条开场的「封面选择与显示位置」挑选五张主题默认封面、固定编号、自动分配或重新随机，并调整横向／纵向取景焦点。自定义封面优先；选择默认图会替换自定义图，保存后随卡导出配置。
- 在「设置 → 开场白 → 点击预览整个选择页」展开完整选择页；编辑草稿时自动同步，可切换 390px 手机／900px 桌面宽度。预览只用于查看，保存后才写入角色卡。
- 作者在逐条开场中填写「分组」和「筛选标签」；一个开场属于一个分组，可带最多 12 个标签。同名分组合并展示，组内保留原顺序；搜索、人物、分组和标签可以组合筛选。分组可折叠，折叠状态在当前窗口保留；旧卡没有分类时沿用原列表。
- 世界书预设集中创建、编辑、复制、重命名、删除，再按开场分配；未分配不改世界书。只修改当前角色绑定书，按 UID 预检，失败回滚。
- 音乐与 LRC/TXT 歌词，需手动播放。上传的封面、音乐和歌词保存到角色卡扩展字段；封面尝试压缩，GIF 保留动图，音频可能增加卡片体积。
- 完整正文预览的「阅读设置」支持三档字号、两档行距与「专注正文」开关；阅读偏好在本机记忆，作者与玩家共用，不随角色卡导出。
- 完整正文在独立窗口中展示大封面、完整简介与全部人物；上一条／下一条只浏览当前筛选结果，底部可直接选择开场。浏览不改变聊天或世界书，关闭保留列表筛选。
- 关闭、切换开场和更新前处理未保存修改。选择继续编辑不会切换开场或替换模块。
- 主题与设置是可拖动浮窗，适配手机。

### 人物识别

仅读取角色绑定主／附加世界书，先提取有明确依据的姓名与别名，再匹配整个开场原文，包括标签、属性、注释和代码块。正文的明确姓名／人物名单在世界书读取失败时仍可识别。
普通触发关键词不能直接当别名，身份不明的词保留待确认；冲突别名不自动归属。标题、属性、分类评级、卡名等弱线索不能单独确认身份，章节与对象语境不能越界。
保存管理名单后，识别与最终显示只使用保留人物，删除项不会经旧字段、别名或其他开场重新加入；恢复自动识别可解除名单限制，不改写世界书。未管理名单时人工规则优先。已保存人物字段留空恢复自动识别，输入「无」明确隐藏。自由文本仍可能漏读或误判，也不能保证区分实际出场和仅被提及。详见 [人物审查](docs/person-matching-audit.md)。

## 更新与通道

本地导入 JSON 只负责远程入口读取、通道校验、备用地址和失败提示。设置中支持手动检查更新与自动检查开关；先显示目标版本及逐版内容，由用户确认后加载。取消同一候选后不再重复弹窗，版本旁仅小星标。
已采用纯远程入口的用户无需在普通更新时重新导入 JSON。v1.0.12 及更早正式入口曾需按 v1.0.13 的既有迁移授权替换一次；之后入口保持稳定。
main 是正式通道，develop 是测试通道，不能同时启用两份脚本。正式／测试固定初始锚点不随运行指针更新。源码成功发布后才可推进指针。

## 当前架构整理

旧 pack.mjs、index.js 和旧分发产物已从当前目录移除。dist 仅保留最新正式入口和测试候选；兼容性回归需要的四份旧入口位于 test/fixtures，历史版本仍在 Git 历史。

全部主题背景在脚本启动时同时预加载，两个 UI 共用缓存与在途请求；界面不等待全部完成。每源超时后尝试备用源，失败保留主题底色。预加载未完成或网络失败时仍可能短暂显示底色。
图标、页眉角饰和设置插画使用固定资源接口；不内嵌图片二进制，不从生成 HTML / CSS 抓取地址。用户自定义媒体仍保存到角色卡。
运行模块约 0.58 MB，最初约 2.22 MB；此数据是文件体积，不代表已测得上传或网络速度。

## 维护者构建

作者与玩家不需要执行此步骤。维护者安装依赖后构建远程模块：

```sh
npm ci
npm run build:preview
npm test
```

preview 仅允许 develop；stable 仅允许 main。构建使用锁定版本 esbuild，从 src/main.js 解析模块图，生成自包含 remote.js、远程 bootstrap 和轻量导入 JSON。generated 与 node_modules 不提交。

Node 回归及 ESM 导出、版本注入、资源哈希、预加载复用检查通过。本轮浏览器与真实 SillyTavern／TauriTavern 保存、导出再导入、触摸和 CDN 可用性尚未验收；当前正式产物专用测试在 preview 模式下仅提示，不算新正式验收。

架构边界见 [架构文档](docs/architecture.md)，交接入口为 [PROJECT_STATE.md](PROJECT_STATE.md)，长期规范为 [AGENTS.md](AGENTS.md)。
