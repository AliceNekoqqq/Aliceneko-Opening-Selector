## 当前规则

1. 人工姓名／别名规则和已保存的人工人物字段优先，重复别名除外。保存设置不把当次自动提取结果冻结成人工人物字段。
2. 明确姓名、本名、全名、人物属性、有效人物姓名表格和明确名单可建立身份。通用 name／名字须有当前人物对象、人物容器、人物资料或性别等证据；缺少语境只保留待确认，不跨开场传播。
3. 普通世界书标题、人物描述、卡名、未知台词署名和人物标签不能独立确认身份。触发关键词不能作为新身份或别名；与确定条目相关的关键词可供人工检查，身份不明的关键词只出现在诊断中。
4. 自动别名须来自有身份依据条目的明确别名字段或速览别名列。别名与其他正式姓名冲突时不覆盖正式身份；多人共用的别名不自动选一个人。
5. 开场匹配仍扫描整个原文，包括所有标签、属性、注释和代码块，不要求动作词。长词优先，英文有单词边界，单字名字有保守边界。名单来源和全文命中是两个阶段。
6. 正文明确姓名可以补充不完整的世界书，并传播到其他开场；待确认候选不传播，空名单／读取失败不抹掉明确姓名。

## 仍存在的准确性边界

- 这是确定姓名的全文提及匹配，不是语义上的“现场出场”判定。一个姓名仅出现在回忆、未出场说明、人物总表或代码中，仍可能命中。保留全文读取是已确认产品规则，不能通过擅自排除标签来解决。
- 正式姓名或明确别名与普通词同形时，如某人物名“春风”，纯字符串规则无法保证区分。手动使用短昵称同样可能产生歧义。
- 明确名单本身若填有普通词，程序无法可靠知道作者是在命名一个虚构人物还是写天气／物品。章节与对象语境能减少误判，不能替代语义理解。
- 收紧证据会增加待确认和漏识别，尤其是只有自由描述、标题或英文通用 name 的资料。人工词表是受控补充入口。
- 旧版人物字段来源不明，只能由用户清空具体误判后保存。本机数据也需在相应修正字段中处理；不会因更新脚本而自动删除。
- 截断上限、1000 人词表上限、单字边界和同名身份仍有限制。世界书改动后应点击“重新读取世界书”。
