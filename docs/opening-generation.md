# 开场白生成 · beta.4

## 产品流程

玩家在普通选择器点击「创建新开场白」，作者在选择页点击「生成开场白」。选人物、设定故事种子、补充要求，调用当前主 API；检查并编辑结果后，点击「加入新建备用开场白」。保存完整正文与选择器标题、人物信息，重新导出角色卡即可分享。

普通单开场卡也显示创建入口；作者主开场已有选择器标记时，可以从零条备用开场开始创作。只在聊天尚未继续、非群聊时使用。

## 本版创作能力

- 主界面独立「人物列表」可保留／移除读取项、补充姓名，保存后按 avatar 在本机持久化，已保留／补充名字正式确认并供两版共用；取消放弃本次编辑，重新读取保留取舍，恢复读取名单需保存才生效。搜索、只看待确认、单人／批量确认、移除待确认、保存并重新识别和恢复自动识别可用；名单供人物识别与生成共用，不会修改世界书或角色卡。
- 世界书人物勾选，展示待确认身份，合并角色卡与已修正人物，姓名可手动增补。
- 自由设定、目的交错的初遇、日常中的异常、被迫合作、秘密线索、关系变化的重逢六种故事种子。搭配时间地点、人物关系／玩家身份、核心画面，自由适配不同世界观。
- 自定义文风与输出语言；可选视角和短／中／长篇幅。篇幅是提示要求，实际长度受主 API 回复上限影响。
- 可选择已有开场作为结构参考，并编辑参考原文；沿用参考标签／状态栏、纯叙事、自定义格式三种输出方式。参考限制为 6000 字，所选人物补充资料最多 12000 字，单条资料最多 4000 字。
- 当前预设模式适配已有写作预设；独立创作提示模式保留角色、玩家和世界书资料，减少预设对正文格式的限制。两者均使用当前主 API，不接管密钥／模型设置。
- 默认排除聊天记录与聊天作者注释，不将原聊天当作剧情起点。提示要求保持人设、留出玩家回应空间、不替玩家行动、不复制参考剧情。
- 新生成版本保留旧草稿；填写修改方向可以调整现有草稿。最近五份草稿和选项按角色、模式保存在本机，关闭／更新／角色切换后可恢复。不会把生成偏好存入分享卡。
- 生成结果在文本框中编辑，不运行生成的 HTML 或脚本。添加前由用户检查状态栏、人设与正文；不会自动选择开场或发送聊天消息。

## 数据与生命周期

- 共享纯规则：`src/opening-generation.js`；主 API 与保存适配：`src/opening-generation-service.js`；共享对话框：`src/opening-generator.js`。
- `generate` / `generateRaw` 是唯一生成入口。请求设置唯一 `generation_id`，静默非流式生成；取消仅调用 `stopGenerationById`，不停止其他请求。接口不支持取消时丢弃迟到结果，在请求结束前不允许叠加新生成。
- 世界书名单沿用现有读取器，额外保留已读取条目用于所选人物资料补充，不重复请求整书；停用条目不补充。关闭补充不等于禁用酒馆自身的世界书扫描。
- 备用正文写入 `data.alternate_greetings`；标题与人物写入 `data.extensions.universal_opening_selector.entries`。作者 metadata 索引从备用 0 开始，玩家包含主开场、从 1 开始；保留原有封面、分类、主题、品牌、音乐、世界书预设和其他扩展字段。
- 保存前读取服务器最新卡片，检查角色、模式与开场列表；保存后再读取并复核。发生冲突不覆盖，失败保留草稿。HTTP 写入和读取无服务器事务锁，最后一次读取与写入之间的其他客户端改动无法完全排除；复核不一致时提示人工检查。
- 仅当前角色、同一聊天、尚无后续消息且消息页与原开场逐条一致时，向当前首条消息追加 swipe，并保持原选择。否则只保存卡片，提示新建聊天使用。聊天同步失败不重复追加角色卡。
- 本机存储不可用时保留窗口内草稿并提示复制；普通关闭需明确点击「仍然关闭」。脚本强制卸载／页面离开无法保证保留未存储草稿。

## 后续方向（本版未实现）

- 可选择的世界书背景包与开场预设联动，避免不同路线的人物／规则混入。
- 一次生成多个不同冲突的候选，标注其区别后选一个；明确展示次数与 API 消耗。
- 作者保存可分享的创作模板：场景槽位、人物槽位、固定状态栏格式。玩家只填槽位，默认模板可被修改。
- 作者批量生成路线开场、同场景不同视角、季节／关系阶段变体；共用生成队列与逐条确认流程。
- 人设、状态栏字段、占位符与格式检查提示；检查不能替代作者／玩家判断，不自动改写已有开场。

优先先验收本版主 API、预设、状态栏和保存兼容性，再推进批量或模板功能。
