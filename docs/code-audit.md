# 当前代码审视（2026-10-07）

审视基线：已发布 develop v1.0.17-beta.9。本轮修复纳入 v1.0.17-beta.10 测试候选。

## 结论

现有纯解析、人物名单规则、资源服务与 UI 已有职责分离，不需要整体推倒。当前主要风险集中在弹窗生命周期、异步读写边界，以及界面文件中混杂的保存实现。下列问题已修复；玩家写卡事务和作者弹窗会话已独立，保持唯一草稿与保存入口。

| 优先级 | 问题及触发条件 | 本轮处理 |
| --- | --- | --- |
| P1 | 生成器等待服务器读取时，当前角色对象被同头像的新对象替换，旧对象的开场指纹仍通过校验，可能忽略新编辑 | 写入前重新取得当前角色对象，检查其身份和开场指纹；新增不写入的回归测试 |
| P1 | 玩家设置有三套单项写卡实现，另有关闭确认的批量实现；不同保存请求可交错，返回后还可能向变更的角色索引写本机扩展 | 单项按钮复用统一保存入口；保存期间锁定控件、阻止重入与关闭，服务器返回后复核当前角色对象及窗口状态 |
| P2 | 作者设置 iframe 被卸载或外部移除，宿主 resize 监听仍保留；未保存确认的 Promise 可能不结束 | 增加幂等强制清理入口，卸载和 iframe 脱离均使用；移除拖动、键盘及 resize 监听，结束确认等待，旧回调停止工作 |
| P2 | 世界书「刷新」按钮的局部变量与刷新函数同名，点击尝试调用 DOM 元素 | 分开变量名称，并使用 finally 恢复按钮；新增通过真实点击处理函数检查刷新、读取失败和草稿保留的测试 |
| P2 | 生成器写卡期间被卸载，迟到的成功结果继续调用 onSaved，可能重新打开已关闭的面板 | 写入返回后检查会话是否关闭；草稿保留，不执行迟到 UI 回调；新增延迟写入回归 |
| P2 | stopGenerationById 返回拒绝的 Promise，同步 try/catch 无法接住 | 明确处理异步拒绝；取消的结果继续被拒收；新增异步取消失败回归 |
| P1 | 玩家面板的人物识别与世界书读取引用未定义的 character，打开／刷新会报错 | 改为当前面板的 cardCharacter；新增真实 mountPlayerSelector 调用链测试，覆盖打开、读取、按钮保存与关闭 |
| P1 | 玩家只凭 HTTP 成功确认写卡，并以旧本机配置作为写入基础，可能覆盖服务器较新的其他设置 | player-card-settings.js 先读取最新配置，只应用所选组，检查开场指纹，写后完整复核配置与开场，再同步本机；复核失败保留编辑并明确提示请求已提交 |
| P2 | 作者／玩家重叠读取时，较旧结果、错误或 finally 可能覆盖较新视图及按钮状态 | latest-request.js 提供共用请求序号，成功、失败与完成状态均检查最新请求和角色／窗口有效性 |
| P2 | 人物名单超过 500 项静默截断后仍显示保存成功；合并补充与确认／删除与排除也可能超限 | 写入前校验去重、取舍后的完整名单及合并结果；超限提示类别和实际数量，保留输入与原存储；编辑器显示数量及容量说明 |
| P2 | 作者正常保存尚未结束时，Escape／关闭确认可能再次发起保存；本机同步完成后仍可能渲染已卸载界面 | 统一保存中标记，阻止重入、关闭与更新；成功后解除保护再关闭，服务器及本机同步返回后均复核当前角色对象与窗口 |
| P2 | 作者删除预设确认在 iframe 外部移除时一直等待；拖动缺少 pointercancel／丢失捕获清理 | author-popup-session.js 统一管理拖动、resize、Escape 与外部移除观察；清理结束两类确认等待，取消捕获并移除所有监听，迟到决策／保存不重复清理 |
| P2 | 写卡成功后人物规则／开场修正忽略本机清理失败，排除字段没有清理旧覆盖；重新打开可能继续采用旧值 | player-override-store.js 统一清理三组覆盖；删除失败尝试写空值，均失败时在本次运行记住清理决策、忽略旧值、显示明确提示并在重新读取时重试；新本机保存成功才替换该决策 |
| P2 | 写卡请求或 JSON 响应停滞，按钮锁定与正在保存状态可能无限等待 | character-card-request.js 为作者设置、玩家设置和生成器写卡的每次网络请求／响应读取提供 60 秒等待上限；超时中止客户端等待，保留编辑并释放保存保护；写入超时明确说明可能已提交，不接受迟到成功 |

人物编辑器的保存、渲染和异步读取状态已展开，减少多种状态迁移挤在一行的维护成本。人物删除、取消勾选和确认的既有产品规则不变。

## 输入与显示检查

- 开场正文预览、候选人物、说明及生成编辑使用 textContent 或输入框，不直接把用户正文执行为 HTML。
- 作者模板 JSON 种子转义 `<`，避免以正文结束 script 标签。
- 封面渲染限制图片 data URL 与 HTTP(S) 地址，并清理 CSS URL 中的引号、反斜杠和换行。
- 人物名单的管理、排除与删除规则集中在纯模块；作者与玩家最终显示均使用名单过滤。

这些是本轮源码检查的结果，不等于完整渗透测试或实际酒馆兼容验收。

## 剩余风险与整理顺序

1. **写卡事务的服务端边界。** 玩家已增加最新读取、开场冲突检测和服务器复核，但各事务仍无法阻止其他插件或设备在读取与写入之间修改卡片。客户端检查不等于服务端原子比较并写入；复核只能发现部分已发生的冲突，无法保证复核以后没有新写入。
2. **界面协调文件仍大。** 作者弹窗事件／会话、玩家网络保存已拆出，但 selector.js 仍持有作者草稿与设置构建，player.js 仍集中构建字段和卡片。后续按具体职责抽出设置构建，避免重复数据与保存状态；不机械按行数拆分。
3. **源码可读性。** 人物编辑器关键状态已展开；生成器、作者 iframe 文档模板与若干旧样式仍有长行。优先整理实际变更涉及的状态迁移和职责，避免全仓无关格式化及末尾叠加覆盖。
4. **受限存储与宿主接口边界。** 本机覆盖清理失败已有会话记忆、提示和重试；当删除及写入均被禁止时，无法把清理决策持久化，重新载入脚本仍可能恢复旧覆盖，因此必须保留提示。网络请求已限定等待时间，但酒馆 writeExtensionField／setChatMessages 等 helper 内部 Promise 不可由本模块安全取消；服务端处理也不会因客户端停止等待而保证撤销。
5. **真实宿主验收。** 本轮事件／状态测试不模拟酒馆 CSS、浏览器布局、手机触摸及接口内部实现。作者弹窗位置、真实跨 iframe 拖动与酒馆写卡／导出仍需实机确认。
